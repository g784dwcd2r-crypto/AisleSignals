# AisleSignals repository working agreement

- Jawahir Q. is the product owner. Implementation is Codex plus bounded agents; do not assume hired engineers or continuous on-call agent operation.
- The accepted offer is EUR 60 monthly for one pharmacy branch. A site registration does not create a charge or paid entitlement. Keep subscription state bound to organisation and site.
- Read docs/handover/implementation-plan.md and business-baseline.json before changing scope. Design version 2.2 supersedes earlier draft staffing and pricing assumptions.
- Delegate independent bounded tasks with owned paths, requirement IDs and test evidence. Avoid concurrent writes to shared contracts or migration files. The coordinating agent integrates and reproduces material checks.
- Distinguish planned, implemented, tested, pushed and deployed. Do not represent schema validation as runtime or hardware acceptance.
- Keep source cameras, adapters and model capabilities explicit. No unsupported universal camera or theft-detection promise.
- Enforce organisation/site/action access at runtime, including media ranges, background jobs, exports and support grants. No client-provided tenant field creates authority.
- Do not commit secrets, camera passwords, customer footage, patient records or real incident narratives. Use clearly labelled synthetic fixtures.
- AI drafts use bounded reviewed facts, cost reservation and human approval. AI cannot actuate outputs, execute arbitrary tools or make identity/criminality findings.
- Optional output work is isolated from AI and gated by physical commissioning, fresh context, signed expiry and persistent duplicate protection. There is no door-lock integration.
- Preserve user work and push ordinary non-destructive commits when authorised. Never force-push as a routine integration step.
- Keep changes reviewable, run meaningful checks appropriate to the change and record unresolved external dependencies in the status log.

- Mandatory no-new-hardware scope: local companion on the existing pharmacy laptop. Do not purchase or design a required new appliance, camera, GPU, capture card, relay or wiring installation. Unsupported existing equipment produces an explicit limitation. Handle sleep/resume, sign-in startup, workload guards and existing speaker tests.

- The first pilot includes one Windows laptop and one Mac. Treat both platform installers and startup/sleep/permissions/audio tests as required for pilot readiness; inventory exact OS and architecture before freezing targets.
