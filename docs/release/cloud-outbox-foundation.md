# Durable cloud outbox foundation

Implemented as an **inactive storage module** for FR002/011/015/016. No Store migration, API hook, browser control, pairing flow, background sender, cloud protocol or backup change enables it. All verification below uses synthetic SQLite records and a synthetic AES key; no network or customer data is accessed.

## Caller contract

`install_schema(conn)` requires an already open caller transaction, uses individual SQL statements and a savepoint, and never commits or changes `PRAGMA user_version`. Its own schema version is 1. Root must coordinate the actual pilot schema/version and backup migration before calling it from the app. Use the existing caller's `BEGIN IMMEDIATE` transaction for concurrency; every storage method likewise requires that transaction. Savepoint rollback preserves unrelated caller work if a bounded outbox error is handled deliberately.

Construct `Outbox(key: bytes, limits: Limits = Limits())` with a separate, already retrieved **32-byte sync key**. It never generates/replaces keys or reads a credential file. `Scope(installation_id, organisation_id, site_id)` must come from server-resolved authority; `BindingRef(id, generation)` must come from the current trusted binding. No dataclass or identifier grants authority. Installation/binding/target IDs are canonical UUIDs; local organisation/site identifiers follow the mapper's bounded ASCII contract. A credential handle is an opaque UUID, never a bearer token or path.

| Public method | Contract |
| --- | --- |
| `create_binding(conn, scope, *, binding_id, expected_generation=0, target, now)` | Caller must explicitly supply generation zero for a new ID. Creates a PAUSED binding; returns `Binding(ref,state,activated_at,target)`. Target has exact HTTPS `origin`, cloud organisation/pharmacy/device UUIDs and credential-handle UUID. One active/paused binding per installation; a cloud device cannot be reused under another binding. Existing IDs conflict; route-level lost-response idempotency belongs to the future pairing integration. |
| `set_paused(conn, scope, ref, *, paused, now)` | Explicitly activate, pause or resume. State changes advance the control generation and invalidate old claims. Resuming keeps the immutable binding UUID, destination and queued payloads, but moves the admission boundary for new work. Returns the new binding/ref. Disconnected/restored bindings cannot resume. |
| `enqueue(conn, scope, ref, mapped_observation, *, now)` | Accepts the mapper's `MappedObservation`. Revalidates the exact five-field historical payload, computes its expected UUID5 from trusted scope/binding/entity identity, checks admission/deadline and current generation, then inserts beside the caller's entity write. Returns local outbox UUID. Exact replay returns the original ID even after payload erasure; changed content/deadline conflicts. |
| `claim(conn, scope, ref, *, now, lease_seconds=15)` | Returns one immutable `Claim` or `None`. Claim contains local ID, ref/token, operation, stable source UUID, immutable payload, lease deadline and exact UTC `admitted_at`/`deadline`. Withdrawals take priority and may proceed while sharing is paused. No disconnected binding can claim. |
| `retry(conn, scope, ref, claim, *, now, delay_seconds)` | Retains identical encrypted bytes/hash/source UUID; clears the completed lease and schedules a bounded 1–3,600-second delay. The future sender chooses jitter/backoff. |
| `acknowledge(conn, scope, ref, claim, *, receipt_id, now)` | Requires a live matching claim and canonical receipt UUID. Erases payload, marks RECEIVED/WITHDRAWN, and preserves stable identity, observation digest and original observation receipt. Exact repeat receipt is safe; changed receipt conflicts. |
| `withdraw(conn, scope, ref, item_id, *, reason, now)` | Reason is LOCAL_DELETED/LOCAL_EXPIRED/LOCAL_EXPORT_REMOVED. Never-attempted observations become terminal with payload erased. Anything ever claimed is an uncertain delivery and moves to WITHDRAWAL in the same reserved row. Earliest withdrawal reason/payload is immutable on repeat. No remote deletion is performed. |
| `expire(conn, scope, ref, *, now)` | Applies the stored deadline: unsent data is erased; attempted/received data gets a withdrawal obligation. `claim` also performs this check. Recorded/synthetic exclusion and source-existence rechecks belong to the mapper/trusted integration, not an entity query in this module. |
| `disconnect(conn, scope, ref, *, now, restored=False)` | Permanently stops new claims, erases never-attempted payloads, preserves/creates uncertain-delivery withdrawal obligations and advances the generation. `restored=True` marks RESTORED. Root's future restore path must explicitly call this for every trusted scope/binding before permitting a sender; copying a database alone does **not** run it. |
| `reject(conn, scope, ref, claim, *, code, now)` | Bounded REMOTE_REJECTED/REMOTE_CONFLICT/LOCAL_CORRUPTION code. A rejected observation creates an uncertain-delivery withdrawal. Rejected withdrawal becomes BLOCKED with payload erased but its identity, reason and unresolved obligation preserved. No automatic remote-resolution claim. |
| `prune_terminal(conn, scope, ref, *, now, limit=500)` | Deletes at most 1,000 selected terminal metadata rows per call, after 31 days since terminal settlement. Only never-attempted CANCELLED/EXPIRED or receipt-confirmed WITHDRAWN rows qualify. Pending, leased, RECEIVED, uncertain or blocked obligations never qualify. Returns removed count; does not re-key anything. |
| `inspect(conn, scope, ref, *, now)` | Latest 200 metadata/status rows plus complete total/withdrawal counts and binding target; never payload bytes or a token. Monitoring is always UNKNOWN. |

Control generation is a mutable publication/lease fence; it is **not** part of the immutable event UUID or encryption identity. Paused backlog survives resume. A separate installation capacity reservation survives cancellation, phase changes and re-pairing until the previous lease expires or valid settlement proves its completion. Thus cancelling a claim does not falsely prove an old HTTP request ended. The future sender must use a request timeout shorter than its lease and maintain one actual network operation; a lease alone cannot terminate a hung request after expiration.

## Encryption, identity and bounds

AES-GCM uses a fresh random nonce and separate `ASOUTBOX1` envelope. Authenticated additional data binds envelope/schema version, installation, local organisation/site, immutable binding UUID, local outbox UUID, operation, millisecond scheduling bounds and exact ISO admission/expiry. Database edits cannot extend a claimed payload's deadline undetected. SQL triggers additionally reject ordinary accidental edits to identity/target/time columns. Millisecond scheduling may conservatively expire a sub-millisecond interval early; the claim retains exact original UTC timestamps for the wire.

Mapper `source_event_id` is UUID5 over the agreed fixed namespace and canonical installation/binding/local-scope/entity identity. `payload_hash` is SHA-256 of canonical **five-field** mapper JSON. `observation_hash` additionally binds the exact immutable ISO deadline for local duplicate conflict checks. Neither is the future v1 cloud **six-field** wire digest: the sender must derive its fixed `expires_at` from `Claim.deadline`, add it to a copy of `Claim.payload`, and use that same six-field canonical content on every retry. This module makes no request to either the legacy or v1 route.

Defaults: 500 pending observations per binding/1,000 per installation; 20,000 total records per binding/40,000 per installation; 1 MiB/2 MiB payload budget; 500 new records per binding per rolling day; 32 retained bindings per installation. Nonterminal records reserve at least 256 bytes for their possible withdrawal, so a full ordinary queue cannot silently discard an uncertain-send obligation. Confirmed-withdrawn or never-attempted terminal records reserve no future payload bytes. A withdrawal reuses the same record, erases the original observation bytes and preserves its original digest/source UUID/receipt. Terminal caps accommodate 500/day × 31 days plus pending work. `prune_terminal` provides bounded 31-day cleanup; root must wire its periodic invocation later. Pending/uncertain obligations can still fill the caps deliberately: resolving delivery/withdrawal is required, and no cap silently deletes them. Do not present this callable foundation as an installed production retention worker.

`KEY_UNAVAILABLE` and `CIPHERTEXT_INVALID` fail closed, do not advance a claim or alter its payload/identity, and never echo content. The future sender must stop/pause and surface the error; it must not repeatedly skip a corrupted head, replace its key, recreate its UUID or assert delivery. Repair with the original key/data is a future operator workflow. A deliberate local withdrawal can cancel a known never-attempted row; uncertain rows retain the obligation. BLOCKED withdrawals and disconnected/restored obligations require later cloud-manager reconciliation; they are never silently declared complete. SQLite I/O failures still propagate to the owning transaction, whose API boundary must sanitise driver errors.
